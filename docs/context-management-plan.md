# 上下文动态管理改造方案

日期：2026-10-15。目标项目：`D:\code\udataHarness`，Java 8，Solon AI 4.1.1。

## 目标与现状

在保证任务质量、关键约束和证据准确性的前提下，让低价值信息退出活跃上下文，并可按需恢复。以实际总费用、任务完成质量和延迟评价，不以压缩比例单独评价。

当前应用通过 UserHarnessEngineServiceImpl 配置 HarnessEngine，使用文件会话仓储。框架已有容量触发压缩、META_FIRST 保护、工具调用配对保护及 Usage 缓存字段。应用配置覆盖框架默认值，须按实际配置建立基线。现有摘要不等于原文归档，向量格式化归档也不保证完整恢复。

参考本地 Open-ClaudeCode（HEAD 2980105）的可核实实现：工具结果外置、读取范围去重、批量结果总预算、替换文本冻结与恢复、共享前缀摘要、压缩后工作状态恢复、增量 Session Memory 和 Cache 变化归因。它是本地恢复与改造版本；缺失的 cachedMicrocompact/contextCollapse/snipCompact 模块不可作为现成能力。受开关控制的功能不可视为默认启用。

## 架构和不变量

1. 原始内容存储：完整文本、内容哈希、来源、调用标识及版本。先持久化成功，再替换；失败保留原文。
2. 活跃视图：决定每次请求看到原文、结构化提炼、预览或引用，与原始内容分离。
3. 检索索引：按 ID、路径、任务和关键词定位原文；后续可选向量召回。
4. 状态按用户、工作区、会话隔离；子代理通过自身会话和调用 ID 隔离。共享拦截器不保存跨会话的可变历史。
5. 不拆工具调用与结果的协议关系；保留错误语义、媒体及 META_FIRST。失败、挂起和 returnDirect 结果采用保守路径。
6. 同版本重复读取仅在旧正文仍在本次 WorkingMemory 中时缩写；旧正文不可见时重新提供必要内容。工具仍正常执行，不缓存执行副作用。
7. 已发送的历史表示冻结；同一调用重复投影得到相同文本。会话恢复不重新生成不同预览。
8. 恢复有体量上限和来源说明；历史快照不冒充当前文件。版本变化后的结论标记待复核。
9. 活跃区淘汰不等于物理删除原始记录。原文保留与垃圾清理单独设计。

## 分期实施

### P0：可逆的工具结果治理（本次首批）

- 在 HarnessExtension 注册 ReActInterceptor 和恢复工具；不修改框架依赖。
- 对可安全处理的大纯文本结果落盘，向模型返回确定性预览、内容哈希、artifactId 和恢复方法。
- 持久化稳定替换文本；调用 ID 重放不覆盖原文，不接受同 ID 对应不同内容。
- 对 read 工具做执行后的精确结果去重：参数、内容一致且原结果仍可见才缩写。
- 增加 context_restore：按会话 ID 精确恢复，分页且限制返回字符量；禁止跨会话恢复。
- 在批结束安全边界实施本批总预算，优先外置最大结果。结果映射与配对信息必须一致；不得改写已发送历史。该项须结合 4.1.1 的真实生命周期验证后接入。
- 配置独立开关、单条阈值、预览长度、批量阈值与恢复上限。默认参数是可调工程起点，不是性能保证。
- 首版用文件＋元数据持久化复用应用现有模式；引入搜索时再评估 SQLite，避免过早增加运行依赖。

### P1：任务状态驱动的收敛与恢复

- 增加 taskId、module、state、dependsOn、supersedes 和 sourceVersion。
- 生命周期：原文保留 ↔ 提炼 ↔ 降级索引 ↔ 归档；按需恢复可回迁。
- 事件：工具大结果、模块切换、Bug 验证关闭、文件修改、任务重新进入。
- 任务记录保留验收条件、结论与证据、修改版本、验证记录、阻塞和下一步。
- 显式状态优先；Todo 勾选不能代替验证证据。关键约束、未解决问题和跨模块依赖硬保护。
- 压缩后只恢复当前任务必需的文件范围、计划和接口约束，避免全文回灌。
- 增加会话级压缩失败熔断和明确降级状态；原文存储失败不能触发不可恢复清理。

### P2：Cache 与成本闭环

- 稳定系统规则、工具定义及序列化顺序；阶段任务快照冻结，状态增量在后部追加。
- 记录最终请求可见前缀变化、上下文管理动作、实际 Usage 与延迟。公共前缀只能表示潜力，不等于实际命中。
- 成本按供应商非重叠类别统计普通输入、Cache Read、Cache Write、输出和工具费用；计入摘要、恢复、重试及子代理，推理 Token 不重复计费。
- 比较保留历史的预计后续费用与本次重组、缓存重建和恢复费用；安全与事实有效性优先。
- 可选共享前缀摘要与独立小模型摘要，实测选择；不假定所有供应商支持缓存编辑。
- 增量记忆记录 coveredUntilMessageId 和来源，成功覆盖之后才归档。

## 验证与实验

离线自动化覆盖：精确原文恢复、预览稳定重放、同 ID 冲突、保存失败、会话/用户隔离、分页边界、Unicode、重复读取及旧正文移出后的重读、错误与媒体保留、工具配对、批量预算、重启恢复、配置开关及真实引擎挂载。

不调用真实模型即可完成首批验证，不访问或变更 API 密钥。后续端到端模型实验单独开展。

实验组：A 当前应用基线；B 仅入场治理；C 生命周期＋恢复＋Cache 决策；另做关闭 Cache 决策的消融。相同仓库起点、模型、权限和预算，多次真实运行；轨迹重放只验证策略，不替代任务质量实验。

指标：隐藏测试通过率、需求与约束准确率、关键证据误删、活跃 Token 曲线、人工抽样低价值占比、工具结果新增量、压缩/超限重试次数、恢复准确率/延迟/体量、实际输入/缓存读写/输出、管理费用和总延迟。收益须实测，不能承诺固定降幅。

现场演示：模块 A 读取与修复 → 大日志 → 验证关闭 → 切换 B → 返回 A 集成修复。临时修改文件、在日志中部埋证据、存储失败和跨会话访问作为随机测试。面板展示上下文组成、动作原因、恢复来源、Cache/费用及验收结果。

### 首批实现边界

- 配置：单条 50,000 字符、本批 200,000 字符、预览 2,000 字符、恢复正文最多 16,000 字符。
- 工具白名单：read/bash/grep/glob/ls/webfetch/websearch/codesearch/lsp。未知工具与结构化图表不改写。
- 错误、非文本、META_FIRST、挂起及 returnDirect 结果保守保留；批量预算为软目标，不能削减时由现有压缩器兜底。
- invocationId 由 runId、Reason turnId 和 wire callId 共同构成，避免兼容供应商跨轮复用 callId 冲突。
- 只外置本次尚未发给模型的结果，不回写已发送历史。重建消息保留配对和来源，清除旧 token_size 缓存。
- 使用本地文件与 Properties 元数据保存原文、哈希、原因、时间和完全一致的预览。无额外模型请求。
- 恢复工具会话参数由框架注入，不出现在模型可选参数中。暂不提供跨会话检索。
- 原文自动过期清理、完整来源索引与版本有效性判定仍在后续范围。
- 已通过真实 Harness＋127.0.0.1 协议桩验证：单结果外置、本批预算、模型看到的下一次请求、context_restore 注入和日志中部证据恢复。没有调用外部模型或使用 API 密钥。
- 新增 14 项上下文存储、拦截器与本地协议集成测试，以及应用配置关闭测试；已有引擎构建测试增加挂载断言。
- 覆盖完整原文和中部证据、重启预览冻结、调用 ID 冲突、会话/用户隔离、Unicode 分页、恢复限额、存储失败、缺失原文、错误与媒体保留、读取变化和正文退出、批量预算及旧历史冻结。
- 复查修复：清除替换消息的旧 token_size；以当前 Reason 消息对象定位本批边界，避免供应商复用 wire callId 时误改旧历史。
- 构建产物：`D:\code\udataHarness\target\udata-harness.jar`。本次未重启运行中的服务、未发布、未提交 Git。
