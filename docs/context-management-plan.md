# 上下文动态管理改造方案

日期：2026-10-15。目标项目：`D:\code\udataHarness`，Java 8，Solon AI 4.1.1。

## 目标与现状

在保证任务质量、关键约束和证据准确性的前提下，让低价值信息退出活跃上下文，并可按需恢复。以实际总费用、任务完成质量和延迟评价，不以压缩比例单独评价。

当前应用通过 UserHarnessEngineServiceImpl 配置 HarnessEngine，使用文件会话仓储。框架已有容量触发压缩、META_FIRST 保护、工具调用配对保护及 Usage 缓存字段。应用配置覆盖框架默认值，须按实际配置建立基线。现有摘要不等于原文归档，向量格式化归档也不保证完整恢复。

参考本地 Open-ClaudeCode（HEAD 2980105）的可核实实现：工具结果外置、读取范围去重、批量结果总预算、替换文本冻结与恢复、共享前缀摘要、压缩后工作状态恢复、增量 Session Memory 和 Cache 变化归因。它是本地恢复与改造版本；缺失的 cachedMicrocompact/contextCollapse/snipCompact 模块不可作为现成能力。受开关控制的功能不可视为默认启用。

## 架构和不变量

1. 原始内容存储：完整文本、内容哈希、来源、调用标识及版本。先持久化成功，再替换；失败保留原文。
2. 活跃视图：决定每次请求看到原文、结构化提炼、预览或引用，与原始内容分离。
3. 检索索引：按 ID、路径、任务和关键词定位原文；后续可选向量召回。
4. 状态按用户、工作区、会话隔离；子代理通过自身会话和调用 ID 隔离。共享拦截器不保存跨会话的可变历史。
5. 不拆工具调用与结果的协议关系；保留错误语义、媒体及 META_FIRST。失败、挂起和 returnDirect 结果采用保守路径。
6. 同版本重复读取仅在旧正文仍在本次 WorkingMemory 中时缩写；旧正文不可见时重新提供必要内容。工具仍正常执行，不缓存执行副作用。
7. 阶段内已发送的历史表示冻结；显式任务暂停/关闭可在 ActionEnd 安全边界重组旧工具正文。
   同一调用重复投影得到相同文本，重组保留调用配对；会话恢复不重新生成不同预览。
8. 恢复有体量上限和来源说明；历史快照不冒充当前文件。版本变化后的结论标记待复核。
9. 活跃区淘汰不等于物理删除原始记录。原文保留与垃圾清理单独设计。

## 分期实施

### P0：可逆的工具结果治理（本次首批）

- 在 HarnessExtension 注册 ReActInterceptor 和恢复工具；不修改框架依赖。
- 对可安全处理的大纯文本结果落盘，向模型返回确定性预览、内容哈希、artifactId 和恢复方法。
- 持久化稳定替换文本；调用 ID 重放不覆盖原文，不接受同 ID 对应不同内容。
- 对 read 工具做执行后的精确结果去重：参数、内容一致且原结果仍可见才缩写。
- 增加 context_restore：按会话 ID 精确恢复，分页且限制返回字符量；禁止跨会话恢复。
- 在批结束安全边界实施本批总预算，优先外置最大结果。结果映射与配对信息必须一致；不得改写已发送历史。该项须结合 4.1.1 的真实生命周期验证后接入。
- 配置独立开关、单条阈值、预览长度、批量阈值与恢复上限。默认参数是可调工程起点，不是性能保证。
- 首版用文件＋元数据持久化复用应用现有模式；引入搜索时再评估 SQLite，避免过早增加运行依赖。

### P1：任务状态驱动的收敛与恢复

- 增加 taskId、module、state、dependsOn、supersedes 和 sourceVersion。
- 生命周期：原文保留 ↔ 提炼 ↔ 降级索引 ↔ 归档；按需恢复可回迁。
- 事件：工具大结果、模块切换、Bug 验证关闭、文件修改、任务重新进入。
- 任务记录保留验收条件、结论与证据、修改版本、验证记录、阻塞和下一步。
- 显式状态优先；Todo 勾选不能代替验证证据。关键约束、未解决问题和跨模块依赖硬保护。
- 压缩后只恢复当前任务必需的文件范围、计划和接口约束，避免全文回灌。
- 增加会话级压缩失败熔断和明确降级状态；原文存储失败不能触发不可恢复清理。

### P2：Cache 与成本闭环

- 稳定系统规则、工具定义及序列化顺序；阶段任务快照冻结，状态增量在后部追加。
- 记录最终请求可见前缀变化、上下文管理动作、实际 Usage 与延迟。公共前缀只能表示潜力，不等于实际命中。
- 成本按供应商非重叠类别统计普通输入、Cache Read、Cache Write、输出和工具费用；计入摘要、恢复、重试及子代理，推理 Token 不重复计费。
- 比较保留历史的预计后续费用与本次重组、缓存重建和恢复费用；安全与事实有效性优先。
- 可选共享前缀摘要与独立小模型摘要，实测选择；不假定所有供应商支持缓存编辑。
- 增量记忆记录 coveredUntilMessageId 和来源，成功覆盖之后才归档。

## 第三批改造：缓存对齐的会话压缩

目标是在同一模型路由下，只用一次摘要请求压缩最旧的完整消息范围。摘要请求复用上一次正式请求的 system、工具定义与消息前缀，末尾追加结构化压缩指令；若前缀无法核对，则只允许无缓存保证的安全路径，不能声称命中。摘要成功且确实缩短历史后，持久化检查点，下一轮装载“检查点＋未覆盖的原始历史”。原始会话消息仍用于历史展示与恢复。

实施顺序：

1. 在最终模型请求拦截点捕获会话、模型、system、工具及有序消息的快照；用本地协议桩比较摘要请求与前次正式请求的逐消息前缀。
2. 用可切换的缓存对齐拦截器替代默认双策略摘要。按模型窗口、输出预留与保留尾部预算选择范围，保持工具调用和结果成组；同模型、同前缀时仅追加末尾压缩指令。摘要调用不执行工具，空摘要、截断、取消与非缩小结果不提交。
3. 在会话目录原子保存摘要、覆盖位置和原始消息校验值。新的会话历史投影只把检查点及其后的原始消息交给模型，不删改面向用户的完整历史；校验失败回退原始历史。
4. 将摘要调用的 Usage、缓存命中、压缩前后 Token、失败原因记入审计。覆盖多轮、重启、审批续跑、子智能体、模型切换、工具配对、无缓存、存储失败与上下文超限。

配置保留 `legacy` 回退模式。已有的工具结果归档、任务档案和按需恢复与会话检查点分层工作，不覆盖用户已写入的数据。DeepSeek 的前缀缓存属于尽力而为：完整前缀和相同路由提供命中机会，是否降低费用以实际 Usage 为准。

### 第三批实施记录：缓存对齐的会话压缩

- `CacheAlignedCompressionInterceptor` 在正式模型请求拦截点保存每会话最近一次成功请求的消息哈希、system 和工具定义；内存最多保留 128 个会话快照，不写入请求正文。压缩时选最旧的工具配对完整范围，使用同一路由、已记录前缀和最后一条结构化 user 指令进行一次摘要调用。摘要请求的最终协议 JSON 会再次比对消息和工具前缀；`cacheAligned` 仅表示协议前缀匹配，不表示提供方实际缓存命中。
- `CompactingFileAgentSession` 与 `CompactionCheckpointStore` 保存摘要、覆盖的原始消息条数和前缀校验值。下一轮模型历史读取“检查点＋未覆盖原文”，`getMessages()` 仍返回完整原始聊天。检查点校验失败时回退原始历史；成功生成较短摘要后先落盘再替换工作记忆。
- `agent.context.compaction.mode` 支持 `cache-aligned` 与 `legacy`；后者继续使用 Solon 默认压缩与原有会话装载。`threshold-ratio`、`retain-ratio` 和 `output-reserve` 可配置。摘要 Usage、估算压缩前后 Token、前缀匹配和失败代码写入既有 token 审计，正文不入审计。
- 本地协议测试覆盖流式与非流式路径的相同模型、system、工具定义和消息前缀，及重启后检查点投影；仓储测试覆盖原始历史保留和失效校验。JDK 8 全量测试与打包通过（84 tests，0 failures/errors/skipped）。提供方实际 Cache 命中与费用尚待真实请求对照，不由本地桩确认。
- 当前 `onReasonStart` 使用同步模型调用；流式任务取消会在摘要返回后阻止提交，但不能在摘要请求等待期间立即中断该请求。会话 Checkpoint 只压缩模型可见历史，不改动用户原始会话文件。工具输出的先期外置与任务档案仍按各自策略运行。

### 第四批：Cache 成本门槛与上下文观察台（2026-10-15）

- 新增 ContextCacheConfiguration/ContextCostPolicy：显式阶段归档先形成无副作用的批量候选，估算减少的 Token。
  使用最近一次同模型调用的缓存占比和按模型别名配置的价格估算后续收益；以整个已缓存前缀作为重建上界，
  加上配置的恢复 Token 预算。收益超过开销乘安全系数才保存并替换旧工具正文。
  未知价格或缓存指标保留前缀；容量压力优先，成本开关关闭时维持原阶段归档行为。
  该门槛不控制压缩器或新结果预算，也不在运行中调用报价服务或摘要模型。
- 新增 ContextUsage：通过实际 Usage 源字段区分缓存读取 0 与字段未报告，支持显式 inclusive/exclusive 输入口径，
  使用互斥普通输入、Cache Read、Cache Write 和输出类别计价。thinking 不重复计费。
  未配置口径时仍保存原始 promptTokens，但归一汇总、命中率与费用可能未知。
- 新增 ContextTelemetryInterceptor：在推理开始采集工作记忆分类与公共前缀估算，在推理结束关联实际 Usage、
  runId/reasonId、模型、耗时与单价快照。状态放在当前 Trace extras，不在共享拦截器保存跨会话历史；
  正文不入观测日志。公共前缀只比较应用层消息、规则和工具定义，不能等同最终供应商缓存前缀。
  重试、压缩后的最终协议与路由补充内容可能与该估算不同。
