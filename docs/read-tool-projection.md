# `read` 工具结果投影

`read` 的完整执行结果与模型可见结果分开处理。默认模型可见预算为 **6000 个 Java 字符（UTF-16 代码单元）**，由 `agent.context.tool-results.read-visible-chars` 配置；这不是 Token 上限。其它工具继续使用原有的单条结果预算。执行本身仍遵守 `read` 的行数、单行长度和字节上限。

| 类型 | 条件 | 模型可见内容 |
| --- | --- | --- |
| `full` | 完整结果不超过预算且不存在更短的安全投影 | 原始结果 |
| `excerpt` | 结果超过预算，且引用/增量不适用 | 明确标注不完整的首段，以及完整历史快照的 `context_restore` 入口 |
| `reference` | 同路径、同参数、同内容的完整读取结果仍在当前工作记忆中 | 指向已有完整结果的简短说明，以及独立的快照恢复入口 |
| `range_delta` | 同路径、同 SHA-256 文件版本，且当前行与可见完整旧行逐行相同 | 明确列出可复用行范围、尚未显示的新行，以及完整快照恢复入口 |

所有非 `full` 投影都先保存原始工具结果；保存失败就保留原文，不发送无法恢复的投影。仅将当前工作记忆里的完整文本结果视为可复用：先前的 `excerpt`、`reference`、归档占位、错误、非文本结果都不能作为行覆盖证据。文件版本变化时，不使用范围增量；改用 `full` 或 `excerpt`。非本地虚拟来源如无可靠版本，也不会启用 `range_delta`。

`reference`/`range_delta` 依赖旧内容在本次模型请求中可见。若之后发生上下文压缩，引用中仍有本次完整结果的恢复入口，但模型需要调用 `context_restore` 才能重新取得正文。行号、版本和覆盖范围由当前 `BoundedReadTool` 的输出格式解析；若格式变化，解析失败会安全退回 `full`/`excerpt`。

评估时同时看投影字符数、实际 API 输入 Token、缓存读取 Token、额外续读/恢复调用、编辑冲突率和任务完成率，避免仅因预算缩小而增加总体成本。
