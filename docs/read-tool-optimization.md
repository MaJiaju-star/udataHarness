# `read` 工具的有界读取

当前应用在 Solon AI 4.1.1 的 `read` 之上注册同名 Talent。仅当 AgentFactory 原本授予代理 `read` 时才注册；工具激活时它排在内置 TerminalTalentProxy 后面，因此覆盖内置实现，不增加代理权限。

本地文件（包括本地逻辑挂载）默认尝试读取 4000 行，`limit` 最多 8000 行；编号正文最多 256 KiB，单行最多展示 64 Ki 字符。达到行数或字节上限时返回下一页 `offset`。超长单行会扫描到下一行，但不缓存整行；输出明确说明该行后半段未返回。扫描使用固定大小的缓冲区，因此内存占用不随文件或单行长度增长。读取完仍触发原有 LSP 预热钩子。对于不超过 16 MiB 的本地文件，后端记录 SHA-256 文件版本，供 `edit/write` 作为修改前提，不在正文中展示摘要。

路径仍经 Solon 内部的 `TerminalSupport.resolveSafePath` 校验，保留工作区、符号链接、挂载点、物化缓存和敏感路径限制。实现使用反射取得同一 `TerminalSupport` 实例；若上游结构改变，会在构建工具时失败，而不会绕开校验。升级 Solon AI 时应优先将有界读取及安全路径解析能力合并到上游公开 API，移除这层兼容实现。

非本地虚拟挂载仍委托 Solon 原始 `read`，保留其权限判断和 10 MiB 来源上限；它尚未使用本地文件的 256 KiB/单行截断策略。

同一会话再次读取同一路径与范围时，工具先计算当前文件 SHA-256。若与上次一致且上次读取快照仍在当前会话的归档目录，返回简短的 `<read-unchanged>` 引用和可恢复的 `@tool-results/<id>.txt` 路径，不再重新扫描行正文或向模型重发正文，也不展示版本摘要。第一次读取在成功后保存快照；保存失败则保留原文且不建立短引用。快照索引最多 512 项，不跨会话共享。大于 16 MiB 的文件不使用这一优化；后置的可见内容投影仍由 `ToolResultContextInterceptor` 负责。

文件身份按路径守卫校验后的真实路径判断，`file.txt`、`./file.txt` 和指向同一文件的本地逻辑路径可复用；范围按默认值及上限归一化后比较。空文件同样支持引用，越界等读取错误不会成为引用来源。即使只请求部分行，版本仍基于整个文件内容计算：文件其他位置变化也会返回新的读取正文。快照丢失时重新读取并建立新的可恢复快照，再次读取才恢复短引用；短引用始终保留原分页的续读提示。

成功读取的 SHA-256 由后端按会话记录，供 `edit/write` 自动校验，模型不需要抄写或传入摘要。新工具结果正文（包括未变化引用、修改成功提示、快照恢复头）不再展示摘要；读取版本通过 `ToolResult.metas.sourceHash` 传递给后端上下文投影，不进入模型请求。历史快照读取不会替当前文件刷新修改基线；收到本次工作区 read 的结果后，应在下一轮工具调用中发起修改。升级前已存储的历史正文仍可能包含旧版本行。

## 历史快照回读

`@tool-results/<id>.txt` 保存的是原始工具结果，可能已包含源码行号、原文件分页提示、日志或补丁。回读只对正文分页，保留已有内容、BOM 和 CRLF/LF/CR，不再添加外层行号。行分页的原样正文位于 `<snapshot-content>` 块内，分页元信息位于块外。

快照 `offset/limit` 按快照自身的物理行计数（含原工具结果的页眉与提示），不是原文件行号。达到行数限制时，续读指令显式携带相同的快照路径。单次快照正文最多 16 KiB；达到字节上限时不丢弃超长行的后半段，而是提供精确的快照 `char_offset`，切换字符分页继续。这个游标按 UTF-16 字符计数，不是 UTF-8 字节数，且不会切开代理对或 CRLF。

字符分页恢复头明确标记 `position_unit=snapshot_utf16_chars`，其中 `offset/next_offset` 都属于快照字符位置；用 read 继续时应传 `char_offset`，不能当作原文件行号或快照行号。快照中原有的源码行号与原工具续读提示保持不变，但只是历史结果；快照回读到末尾不表示原文件已完整读取，也不会刷新当前文件的修改基线。原命令捕获不完整时，回读仍明确告知只恢复了已捕获部分。
