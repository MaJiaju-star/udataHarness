# 流式命令日志与结构化编辑差异

## 同步 bash

生产环境的 `BashCaptureTalent` 在原 `TerminalTalent.bash` 安全路由内安装执行适配器，只替换当前同步 bash 的输出捕获。原 argv、工作目录、实时 PATH、shell 编码识别、PowerShell CLIXML 过滤、沙箱包装和审批保持不变。Python/Node 等其他执行路径仍委托原执行器，`bash_start/wait/stop` 不在本轮范围内。

输出增量解码为 UTF-8 文本并写入当前用户、工作区、会话隔离的归档。内存只保留有界首尾片段；进程和输出管道结束后才提交快照元数据。模型得到执行状态、退出码及 `read(file_path="@tool-results/<id>.txt")` 恢复入口，结构化捕获信息放在内部 `bashOutput` 元数据中。二进制输出不直接展示正文；归档是解码文本，并非原始二进制文件。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `agent.context.tool-results.bash-visible-chars` | 20000 | 正文展示预算，实际限制在 600–64000 字符；状态与恢复入口另计 |
| 工具参数 `max_output_chars` | 20000 | 可进一步缩小本次正文展示，不扩大服务端预算 |
| `agent.tools.bash.max-log-bytes` | 268435456（256 MiB） | 单次命令独立存储配额，允许配置 1 字节至 1 GiB；原始输出和 UTF-8 归档字节都受约束 |
| 工具参数 `timeout` | 120000 毫秒 | 执行时间限制，不随展示预算变化 |

显示截断不再导致 1 MiB 杀进程。超时、线程取消、日志配额或持久化失败才会终止进程树；超时和配额后的可恢复前缀标记 `capture_complete=false`，后续 read 恢复时仍明确说明不完整。归档创建失败时不启动命令；持久化失败不宣称已保存完整日志。单次配额不等于总磁盘配额，日志保留与磁盘容量仍需部署侧管理。

即使关闭通用工具结果压缩，基础归档仓储仍启用，以保证 bash 日志和大补丁恢复入口有效。上下文拦截器不再把流式 bash 的展示片段当作完整日志重新归档。直接使用不带仓储的旧构造入口仍保留原执行器行为，生产接线使用带仓储的构造入口。

## edit 差异

`edit` 保留现有会话版本冻结、读前写门槛和原子替换。根据本次实际修改前后的正文准备 unified diff，只有文件成功提交才发布 `editDiff` 元数据并归档大补丁；失败或无变化时不产生成功差异。

结构包括 `filePath`、`addedLines`、`deletedLines`、`firstChangedLine`、`hunks`、`patch`、`truncated`，大补丁另有 `patchPath`。SSE 和历史会话回填只选择 `editDiff/bashOutput`，不会泄漏 `sourceHash` 等其他内部元数据。模型收到简短成功统计，不重复接收完整补丁。

前端工具卡片显示变更统计和着色补丁，子智能体工具同样适用。补丁预览最多 64000 字符，最多保留 200 条差异区间元数据；超过时明确标注，并可用 read 分页查看完整补丁。归档失败不把已经成功的编辑误报成失败。

为避免大文件触发昂贵的差异算法，前后行数乘积超过 4000000 时使用共同前后缀定位后的合并差异块，并标记 `coarse=true`。该模式统计可能包含块内未变行，不应视为最小变更行数。BOM 与 CRLF 的原文件保留策略不变；补丁统一按 LF 展示，并明确标注末尾无换行的行。

执行器适配依赖 Solon 4.1.1 的内部 executor 字段，与已有路径守卫兼容层一样，框架升级时须运行兼容测试。不兼容时初始化失败，不绕过原安全路由。
