# 核心文件工具加固

## 本轮范围

- `read`：本地文件输出有界；不超过 16 MiB 的文件由后端记录 SHA-256 版本，不在工具正文中展示。
- `write`：新建文件无需先读；覆盖已有本地文件必须在当前会话先 `read`。后端自动维护并核对已读 SHA-256，工具参数不再包含 `expected_sha256`。同目录临时文件写入完成后使用原子移动替换，并尽量保留原文件的 POSIX 权限或 Windows ACL；不支持原子移动的文件系统会拒绝写入。
- `edit`：当前会话先 `read`，后端自动核对版本，最多编辑 16 MiB 的文件；沿用 Solon 的文本块匹配、缩进、换行和 BOM 逻辑，全部修改成功后才替换目标文件。版本冲突不写入。
- `ls`：本地目录默认返回 100 项、最多 500 项和 50,000 字符；按相对路径字典序用 `after` 续页，递归深度仍为三层。扫描目录时仅保留当前页候选项，不在内存收集整个目录。
- `bash`：仍经 Solon 的 shell 翻译、命令校验、OS 沙箱和审批路由；同步执行的日志改为流式归档，有界首尾展示不再终止命令。超时、取消、独立日志存储配额和磁盘故障仍会停止执行并标注原因。

上述同名工具只在 Solon 原本已授予代理对应能力时挂载，不向其他代理新增权限。本地路径仍交给 Solon 的 `TerminalSupport.resolveSafePath` 校验；若 Solon 4.1.1 的内部结构变化，构造工具会失败，而不会绕过校验。

## 后端会话版本

`SessionFileVersions` 由同一工作区引擎中的 `read/edit/write` 共享，按会话和文件真实路径记录成功读取的版本；重复 read 返回引用时也保留该基线，读取历史快照不会更新当前文件版本。一个会话的读取不替另一个会话授权修改。覆盖或编辑时先核对当前文件，落盘前再次核对；写入成功后记录本工具实际写入字节的摘要，后续模型轮次可继续修改。

每批工具调用在执行前冻结已读版本，批次 ID 通过隐藏上下文注入，不暴露给模型。同批 `read + edit/write` 不会让新读取替已生成的编辑更新前提；同批连续修改同一文件时，第一次修改后的其他修改需在下一轮重新决定。同一批审批恢复沿用原基线，审批期间外部改动仍会触发冲突。版本只保存在引擎内存中，服务重启或引擎重建后必须重新 read；缺少基线时不会按磁盘当前内容自动放行。

## 限制与后续

非本地虚拟挂载仍委托 Solon 原始实现，尚不适用本轮的本地版本前提、分页和原子替换。`ls` 游标以路径名为依据，目录在两页之间变化时可能出现重复或遗漏；需要强一致列表时应引入目录快照。原子移动保证不会把半写文件暴露给读者，但不能单独解决外部进程在最后一次版本检查与移动之间的竞态。建议在后续 Solon 版本中提供公开的路径校验与原子文件操作接口，替换当前兼容层。
