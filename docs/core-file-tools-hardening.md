# 核心文件工具加固

## 本轮范围

- `read`：本地文件输出有界；不超过 16 MiB 的文件附带 SHA-256 版本。
- `write`：新建文件无需版本；覆盖已有本地文件必须传入最近 `read` 返回的 `expected_sha256`。同目录临时文件写入完成后使用原子移动替换，并尽量保留原文件的 POSIX 权限或 Windows ACL；不支持原子移动的文件系统会拒绝写入。
- `edit`：本地文件必须传入 `expected_sha256`，最多编辑 16 MiB 的文件；沿用 Solon 的文本块匹配、缩进、换行和 BOM 逻辑，全部修改成功后才替换目标文件。版本冲突不写入。
- `ls`：本地目录默认返回 100 项、最多 500 项和 50,000 字符；按相对路径字典序用 `after` 续页，递归深度仍为三层。扫描目录时仅保留当前页候选项，不在内存收集整个目录。
- `bash`：保留 Solon 已有的执行超时、退出码、输出截断、OS 沙箱以及应用层审批；本轮不改动该安全边界。

上述同名工具只在 Solon 原本已授予代理对应能力时挂载，不向其他代理新增权限。本地路径仍交给 Solon 的 `TerminalSupport.resolveSafePath` 校验；若 Solon 4.1.1 的内部结构变化，构造工具会失败，而不会绕过校验。

## 限制与后续

非本地虚拟挂载仍委托 Solon 原始实现，尚不适用本轮的本地版本前提、分页和原子替换。`ls` 游标以路径名为依据，目录在两页之间变化时可能出现重复或遗漏；需要强一致列表时应引入目录快照。原子移动保证不会把半写文件暴露给读者，但不能单独解决外部进程在最后一次版本检查与移动之间的竞态。建议在后续 Solon 版本中提供公开的路径校验与原子文件操作接口，替换当前兼容层。
